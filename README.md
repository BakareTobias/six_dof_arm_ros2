# Vision-Guided Robotic Manipulation Pipeline using ROS2, MoveIt2, and Gazebo for Automated Object Sorting.

A ROS2 project that models and controls the Franka v3, a 7 degree of freedom robotic arm using rviz and moveit. The project includes a gazebo simulation of the robot performing pick and place tasks guided by computer vision.

## Package Architecture
This project includes the following packages:
- panda_description: urdf files, meshes, and models
- panda_bringup: launch files, config files, rviz and gazebo world files
- panda_controller: slider control launch file and node
- panda_moveit_config: config and launch files generated by the moveit setup assistant
- panda_vision: computer vision node 
- my_robot_interfaces: custom message types 
- my_robot_commander_cpp: C++ nodes for controlling the robot

## Project Pipeline
Camera → Color Detection → TF Transform → MoveIt Planning → Pick and Place Execution

## Requirements
- Ubuntu 24.04
- ROS2 Jazzy
- Gazebo
- Moveit
- Docker*
- Python 3.10
- C++17
- cv_bridge, scipy python packages

*_Docker is used to run the moveit setup assistant on ROS2 Humble in a containerized manner, due to a bug that causes the Jazzy version to crash spontaenously_

## Installation
1. Clone the repo
   ```bash
   git clone https://github.com/BakareTobias/pap_arm_ros2.git
   cd pap_arm_ws/
   ```
2. Install dependencies:
   ```
   rosdep update
   rosdep install --from-paths src --ignore-src -r -y
   ```
3. Build and source 
   ```
   colcon build --symlink-install && source ~/.bashrc 
   ```

## Usage
1. Visualize the robot in rviz
   ```
   ros2 launch panda_bringup display.launch.xml
   ```
2. Visualize the robot with Moveit
   ```
   ros2 launch panda_bringup moveit_launch.xml
   ```
3. Visualize the robot in gazebo
   ```
   ros2 launch panda_bringup gazebo_launch.xml
   ```
4. Writing commands to the robot:
   To interact with the robot with the following commands, first run
   ```
   ros2 launch panda_bringup simulation.launch.xml
   ```
   - __Send robot to a named position__ ( e.g. home, pre_pick)
     ```
      ros2 topic pub --once /named_target std_msgs/msg/String "{data: pre_pick}"
     ```
   - __Give robot a set of joint targets(Forward Kinematics):__ ensure to provide an array of EXACTLY SEVEN floats to match the seven joints of the robot e.g.
     ```
      ros2 topic pub --once /joint_target my_robot_interfaces/msg/JointTarget "{joint_angles: [0.5, 0.4, 0.3, 0.4, 0.0, 0.1, 0.0]}"
     ```
   - __Give robot a goal position and orientation(Inverse Kinematics):__ ensure to provide minimum SIX values for position and orientation(provided in radians).
      A seventh argument determine if the robot should move to this new goal along a straight path(Cartesian Planning*), and it is set to False by default. e.g
      ```
      ros2 topic pub --once /pose_target my_robot_interfaces/msg/PoseTarget "{x: 0.2, y: 0.3, z: 0.4, roll: 0.2, pitch: 0.4, yaw: 0.0}"
      ```
      *_Note that activating cartesian planning constrains robot motions and may cause some movements to fail_
   
   - __Open the robot claw:__
      ```
      ros2 topic pub --once /open_gripper example_interfaces/msg/Bool "{data: true}"
      ```
   - __Close the robot claw:__
       ```
      ros2 topic pub --once /open_gripper example_interfaces/msg/Bool "{data: false}"
      ```
5. Running the CV guided pick and place task: Running this activates a sequence where the robot picks up the three blocks on the table,
   and places them in the bin located behind the robot. By alternating between test_world.sdf & test_world_2.sdf, you can change the starting positions of the blocks 
      ```
      ros2 run panda_vision color_detector
      ```

## Troubleshooting and Known Issues

- On loading simulation, sometimes controllers fail to spawn. Confirm active controllers using ``` ros2 control list_controllers ``` and activate the dead ones using:
   - ``` ros2 run controller_manager spawner arm_controller```   
   - ``` ros2 run controller_manager spawner gripper_controller```
   - ``` ros2 run controller_manager spawner joint_state_broadcaster```

- /move_group parameter: bug in ROS2 where you can not set the use_sim_time parameter for move_group node in the launch files. setup in terminal using
   -  ``` ros2 param set /move_group use_sim_time true```
     
- trajectory execution parameters: the allowed_execution_duration_scaling parameter ``` panda_moveit_config/config/moveit_controllers.yaml ``` is increased to compensate for my laptops slow processing speeds.
